# OpenMC → Geant4 coupling

Examples that couple [OpenMC](https://openmc.org) neutron transport to Geant4
detector response through
[geant4-python-application](https://github.com/lobis/geant4-python-application).
OpenMC records the particles leaving a source region (a surface source); Geant4
starts those particles in a detector and simulates its response.

| Folder | What it does |
| --- | --- |
| [`openmc_coupling`](openmc_coupling) | 14.1 MeV neutrons through 30 cm of concrete in OpenMC, then energy deposition in a plastic scintillator in Geant4 |
| [`msr_coupling`](msr_coupling) | MSRE-inspired molten salt core in OpenMC (eigenvalue mode), then the pulse-height spectrum of an ex-core He-3 counter in Geant4 |
| [`cmfx_recreation`](cmfx_recreation) | Recreates the OpenMC + Geant4 calibration of an EJ-301 scintillator from the CMFX fusion yield paper (Ball et al., arXiv:2505.23047) |
| [`msre_benchmark`](msre_benchmark) | MSRE first-criticality benchmark in OpenMC, with sensitivity variants |

Each folder has its own README with the steps to run and the results.

## Installation

Create a fresh virtual environment first; mixing these packages with an
existing Python installation is the most common cause of library errors.

```bash
python3 -m venv coupling-env
source coupling-env/bin/activate
python -m pip install --upgrade pip
pip install geant4-python-application awkward numpy matplotlib h5py
```

OpenMC is installed separately (see the
[OpenMC installation guide](https://docs.openmc.org/en/stable/quickinstall.html))
and needs `OPENMC_CROSS_SECTIONS` pointing to a nuclear data library. OpenMC
and Geant4 can live in separate environments: the steps exchange data through
files in each folder's `results/`.

## Results

Figures, summaries, OpenMC model inputs and tally output are committed under
each `results/` folder. HDF5 statepoints, surface sources and `.npz` hand-off
arrays are large and are regenerated by the scripts, so git ignores them.
